## Abstract

This document adds the **Execution Sandbox** harness primitive to ADP. The LangChain article rates bash/code execution as the #2 agent harness primitive: rather than pre-defining all tools, give the agent a sandbox to execute arbitrary code. This is distinct from `runtime.execution` (how the agent itself runs) — it's the code-execution capability the agent can invoke during a run.

## 1. `tools.sandbox[]` Entries

```yaml
tools:
  sandbox:
    - id: "python-exec"
      runtime: "python"            # python | node | bash | browser | custom
      version: "3.12"
      image: null                  # null = runner's default image; or OCI image ref
      provider: "docker"           # docker (default) | e2b | modal | daytona | vercel | cloudflare | runloop | blaxel | custom
      mounts:
        - source: "workspace"      # "workspace" = mount workspace.root; or a literal path
          target: "/workspace"
          read_only: false
      env:
        PYTHONPATH: "/workspace"
      snapshot:
        enabled: false             # if true, runner snapshots env after each invocation
        restore_on: "failure"      # failure | always | never
      policy:
        timeout_ms: 30000
        max_output_bytes: 1048576  # 1 MB output cap; excess is truncated
        network: "none"            # none | host | bridge
        allow_filesystem_writes: true

    - id: "bash-exec"
      runtime: "bash"
      provider: "docker"
      policy:
        timeout_ms: 10000
        network: "none"
        allow_filesystem_writes: false

    - id: "browser"
      runtime: "browser"           # headless browser (Playwright/Puppeteer); network required
      provider: "docker"
      policy:
        timeout_ms: 30000
        network: "bridge"          # browser needs outbound network access
        allow_filesystem_writes: false
```

## 2. Flow Graph Binding

A `tool` node that references a sandbox tool ID executes the sandbox:

```yaml
nodes:
  - id: "run-tests"
    kind: "tool"
    tool_ref: "python-exec"
    params:
      command: "pytest tests/ -v"   # or generated by the LLM in the prior llm node
```

The sandbox is invoked with the `command` from `params.command`. Output is returned to `state.tool_responses["run-tests"]`.

## 3. Self-Verification Loop Pattern

The canonical self-verification loop (maps to LangChain article pattern):

```yaml
nodes:
  - id: "codegen"
    kind: "llm"
    model_ref: "primary"
  - id: "run-tests"
    kind: "tool"
    tool_ref: "python-exec"
    params:
      command: "pytest tests/ --tb=short 2>&1"
  - id: "verify-loop"
    kind: "loop"
    body_nodes: ["codegen", "run-tests"]
    termination:
      condition: "context.run-tests.exit_code == 0"
      max_iterations: 5
      on_max_exceeded: "fail"
```

## 4. Credential Isolation Rule (Normative)

Secrets declared in `runtime.env_secrets[]` or resolved from `auth.env_var` references MUST NOT be automatically injected into sandbox `env` blocks. The sandbox execution context is isolated from harness credentials to prevent prompt injection attacks from exfiltrating API keys.

If a sandbox legitimately needs a credential (e.g., to call an API from within the sandbox), the manifest MUST explicitly declare it in `tools.sandbox[].env` using a separate non-secret env var.

**This aligns with the OpenAI Agents SDK principle**: "harness holds credentials; compute context does not."

---

## 5. Sandbox ↔ Workspace Permission Precedence Rule (Normative)

`sandbox.policy.allow_filesystem_writes: false` is the **coarse gate** — no writes regardless of `workspace.permissions.write[]`.

If `allow_filesystem_writes: true`, the runner MUST additionally enforce `workspace.permissions.write[]` glob patterns as the fine-grained path filter.

**Both layers must permit a path for a write to succeed.**

## 6. Semantic Validation Checks

- **Check 27**: `tools.sandbox[].policy.timeout_ms` MUST be present (no unbounded sandbox execution)
- **Check 28**: `tools.sandbox[].mounts[].source: "workspace"` requires a `workspace` section to be declared
- **Check 29**: any tool in `tools.http_apis[]`, `tools.mcp_servers[]`, or `tools.sql_functions[]` with `load_strategy: "on_demand"` MUST have a non-empty `description` field. `tools.sandbox[]` entries are excluded — they do not define `load_strategy` and are invoked via explicit `tool_ref` in flow nodes, not loaded into the system prompt.
- **Check 32**: `tools.sandbox[].snapshot.enabled: true` requires the provider to declare snapshot capability; runners MUST emit a warning if `provider: "custom"` and `snapshot.enabled: true` (custom providers may not support snapshots)
